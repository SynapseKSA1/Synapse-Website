# Synapse (سِنابس) Website

Jekyll-based static site for Synapse KSA, a non-profit for data and AI in Jeddah.

## Project structure

- `pages/`: every page (`index.html`, `blog.html`, `KidsAIBootcamp.html`,
  `Organizational_structure.html`, `Previous_meetings.html`), each with front matter
  `layout:` and an explicit `permalink:` so its URL stays root-level (e.g. `pages/index.html`
  still serves at `/`) even though the source file lives in a subfolder
- `_layouts/`: page templates (`default`, `landing`, `post`)
- `_includes/`: shared `<head>`, header nav, footer, breadcrumbs, and small per-page partials
- `_posts/`: blog articles (Markdown, one per file, `YYYY-MM-DD-title.md`)
- `CSS/`: stylesheets; `CSS/variables.css` holds every shared design token, see the
  `clean-code-static-site` skill before adding new CSS
- `js/`: page-specific scripts
- `Assets/logos/`, `Assets/images/`, `Assets/team/`, `Assets/fonts/`: media, split by purpose
- `.claude/skills/`: `synapse-brand-style` and `clean-code-static-site`, read these before
  making design or code changes here
- `robots.txt`, `llms.txt`: crawler access rules for search engines and AI answer engines,
  see **SEO & AEO** below
- `_archive/`: retired pages kept for reference, excluded from the built site
- `note/`: informal dev changelog, not site content

## Local development

Jekyll needs a modern Ruby (3.0+). The system Ruby on macOS is usually too old, so install one
via Homebrew rather than touching the system install:

```bash
brew install ruby
export PATH="/opt/homebrew/opt/ruby/bin:$PATH"   # add to your shell profile if you want this permanently
bundle install
bundle exec jekyll serve
```

Then open `http://localhost:4000/`.

## SEO & AEO

Every page and post needs `title`, `description`, and `image` front matter. `image` must be the
**object form**, not a plain path string, so `jekyll-seo-tag` can emit `og:image:width` /
`og:image:height` (social previews render unreliably without real dimensions):

```yaml
image:
  path: /Assets/images/example.jpg
  width: 1200
  height: 630
```

When referencing it in a template, use `page.image.path` (or `post.image.path`), never
`page.image` directly, that was a real regression once (it stringifies the whole hash into the
URL instead of the path).

Where each piece of structured data lives, so nothing gets duplicated by accident:

- **Sitewide `NGO` schema + meta/OG/Twitter tags**: `_includes/head.html`, via the hand-written
  JSON-LD block and the `{% seo %}` tag. `{% seo %}` also auto-generates a `BlogPosting` schema
  for every document in the `_posts` collection, complete with the image object above, don't
  add a second, hand-written `BlogPosting` block in `_layouts/post.html`, that was tried once and
  produced two duplicate schema blocks on every post.
- **`BreadcrumbList`**: `_includes/breadcrumbs.html`, included automatically by
  `_layouts/default.html` (and therefore by `post.html`, which extends it). Skipped on the
  homepage (nothing to show a trail against) and on the `landing` layout (deliberately
  chrome-free conversion pages). Give a page a `breadcrumb:` front matter field when its `title:`
  has a suffix (like `"... | سِنابس"`) that shouldn't appear in the trail.
- **`FAQPage`**: driven by a page's own `faq:` front matter list (see `KidsAIBootcamp.html`),
  rendered in `_layouts/landing.html`. Only add this where there's a real, visible FAQ section on
  the page, don't mark up content that isn't there.

Other pieces:

- **`llms.txt`** (repo root): a curated Markdown summary for AI crawlers/answer engines. The blog
  post list is generated by a Liquid loop over `site.posts`, so it never goes stale, but if you
  add a whole new *page* (not a post), link it there manually too.
- **`robots.txt`**: explicitly allows `GPTBot`, `ClaudeBot`, `Google-Extended`, and
  `PerplexityBot` ahead of the generic `User-agent: *` rule. The generic rule already allows
  everything, but naming the AI crawlers is the safer, recommended practice, don't remove them as
  "redundant."
- **Content structure**: every blog post answers its core question in the first 40-60 words, then
  uses question-shaped `## H2` headings for the rest. This is what AI answer engines actually
  extract and cite, not keyword density.

## Pushing to GitHub

```bash
git add .
git commit -m "Your commit message"

```

## GitHub Pages

The included workflow (`.github/workflows/jekyll-gh-pages.yml`) builds and deploys on every push
to `main`. In the repo's **Settings → Pages**, set **Source** to **GitHub Actions**.
